# next_key takes a shared reference

## Refactoring Goal

`KeySource::next_key` is declared `fn next_key(&mut self)` in `src/key_source.rs:8`, but no implementation ever writes to itself. `TtyKeySource` holds two `RawFd`s and copies them out on every call; `tty::read_key` keeps no cross-call state at all — the escape-sequence accumulation is a local `String` built and returned within one call (`src/tty.rs:124-167`), and the only real mutable state in the tty, the resize pipe's write end, is the process global `RESIZE_WRITE_FD` (`src/tty.rs:8,111`). The `&mut self` is a lie, and it costs something: it forces `&mut` borrow discipline on both consumers. There is no user story. This spec only changes signatures.

## Technical Design

Decisions:

- **`next_key` becomes `fn next_key(&self)`.** A key source is a stateless observer of the tty. Escape-sequence assembly is `tty::read_key`'s job, not the source's, so the source has no reason to be handed out mutably. If a stateful source (a pushback buffer, a key coalescer) is ever needed, the signature churns then and it churns for a real reason.
- **`DreController.keys` stays `Box<dyn KeySource>`.** It must own it — `DreController` has no lifetime parameter (`src/editor/controller/mod.rs:21-27`) and its siblings `Screen`, `Reducer` and `EffectExecutor` are all owned trait objects. `self.keys.next_key()` at `:51` compiles unchanged, because a `Box` gives a shared borrow through `Deref` for a `&self` method.
- **`flex::run_loop` takes `keys: &dyn KeySource`** (`src/flex/mod.rs:59`), dropping `&mut`. Dynamic dispatch is kept: `KeySource` is a peer of `FlexScreen` right next to it, and both are injected the same way.
- **`flex::start` passes `&TtyKeySource { fd, resize_fd }`** (`src/flex/mod.rs:97`), borrowing the temporary instead of mutably borrowing it.
- **Scope is `KeySource` only.** The `&mut` signatures on `Screen`, `Reducer` and `EffectExecutor` are out of scope. `DreController::run(&mut self)` keeps `&mut self` regardless, because those three collaborators genuinely need it.

### The four `flex` tests

All of them fully configure the mock before entering the loop, so handing out `&keys` alongside `&mut screen` needs no restructuring — the two are separate locals, so the borrows don't conflict:

- `renders_before_each_key_and_stops_after_ctrl_c` — `run_loop(&keys, &mut screen)` (`:185`)
- `renders_the_text_as_it_is_typed` — `:213`
- `resizes_on_tty_resize_without_reducing` — `:267`
- `renders_before_each_key_and_stops_after_q_in_move_mode` — `:287`

`MockKeySource` is regenerated by `mockall::automock` from the trait, so `&self` on the mock follows automatically. `let mut keys = MockKeySource::new()` stays `mut` everywhere, because `expect_next_key()` configures through `&mut`.

### The `editor::controller` tests

Unchanged. They configure their own local `MockKeySource` and then build the controller, so no test signature moves.

### Verification

- `make test` passes, unchanged test count.
- `make clippy` is clean.
- `grep -rn "next_key" src` shows no `&mut` anywhere: the trait declaration is the only `&self`-shaped one, and `flex::run_loop` no longer takes `&mut dyn KeySource`.
