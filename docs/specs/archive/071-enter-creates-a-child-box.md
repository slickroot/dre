# 071: Enter creates a child box

## User Story

As a user building a diagram, I can press Enter while typing a box's label to finish that box
and drop straight into a new, empty child box — one key instead of Esc then `b`.

## Acceptance Criteria

- While typing a label, pressing Enter finishes the box and a new empty child box appears below, ready for me to type its label
- Pressing Enter on a box whose label is still empty still creates an empty child box
- The action is undoable
- The start-up/README guidance shows Enter as the way to add a child box while typing

## Technical Design

### Key detection
- Enter arrives in raw mode as `"\r"`, the same byte `save_prompt_mode` already maps to its confirm key (`src/save_prompt_mode.rs:15`). `insert_mode::parse` maps `"\r"` to the new command; `"\n"` stays ignored to match the existing convention.

### Command model (`src/insert_mode.rs`)
- Add a new variant `Command::CommitAndAddChild` to the `insert_mode::Command` enum; `Command::Commit` (Esc) stays as-is.
- `Command::Commit` and `Command::CommitAndAddChild` share one pad-trim step: drop the trailing `PAD` and leave the trimmed label.
- `CommitAndAddChild` sequences in `reduce`:
  1. trim the pad on the selected box's label
  2. `snapshot`
  3. `add_child_box`
- Repeated Enter drills deeper for free: each Enter commits whatever box is being typed and adds a child of it, then selects that new child (still in insert mode), exactly mirroring repeated `b`.

### Shared child-creation helper (`src/state.rs`)
- Move the body of `command_mode::new_box` into `state.rs` as `add_child_box(state: State, selected: Option<Path>) -> State`:
  - grows a child under the selected node (or top-level when `selected` is `None`),
  - descends the `Path`, sets `selected` to the new child, enters `Mode::Insert`.
- `command_mode::reduce`'s `NewBox` keeps its current contract inline: `snapshot` then `add_child_box`.
- `state.rs` remains the single owner of box-tree mutation; `grow`/`children_at`/`at` already live there.

### KeyBinding type
- Move the `pub(crate) struct KeyBinding` from `command_mode` into `state.rs`. `command_mode::COMMAND_KEYMAP` and the new insert-mode keymap const both use the shared type. Avoids a new mode-to-mode dependency.

### Undo semantics
- Enter is one atomic, undoable action. Because the snapshot is taken after the label is committed but before the child exists, `u` (after an escaping `Esc`) removes only the child and lands selection back on the finished box — byte-for-byte the same outcome as today's `Esc` then `b` then `u`.
- Ongoing insert-mode typing after Enter remains non-undoable, consistent with existing behaviour (`command_mode.rs:896`).

### README / guidance
- No on-screen hint; guidance lives in the README.
- The README gains a second, machine-generated keymap table for insert mode, mirroring the command-mode mechanism:
  - rows: `Enter` → "Finish the box and add a child box", `Esc` → "Switch to command mode", `Backspace` → "Remove the last character"
  - "any printable character appends to the label" stays as a sentence after the table
  - bounded by its own `<!-- ... -->` markers, generated by a `format_keymap_markdown()` in `insert_mode`, and enforced by a new sync test mirroring `readme_keymap_table_stays_in_sync` (`src/command_mode.rs:353`; regenerate with `UPDATE_README=1 cargo test`).
- Correct the existing "Other keys" wording: Esc "commits or cancels the edit" becomes "switch to command mode".

### Test criteria
- Enter while typing: label is committed with the pad trimmed, an empty child box appears below, insert mode is active on the child.
- Enter on a pad-only (empty) label: same path yields an empty child.
- Undo after Enter + Esc reverts the child and keeps the label.
- Repeated Enter creates child, grandchild, ... (drills deeper).
- README insert-mode table stays in sync with `insert_mode::parse`.
